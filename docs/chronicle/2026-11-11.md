### Chronicle

#### Decisions
- A new entity type is a direct edit once the graph's owner says yes. A graph-init re-interview is optional and never required, because it rewrites only `.commons.yml` and leaves the generated skills' type lists stale. This landed in both templates, in graph-init's Orient step, and in a superseding delta plus a knowledge-graph delta (0.8.0).

The same day it was replaced by title matching: the list made every future author enumerate numberings, and a missed one becomes a permanent skip.
- `supersedes:` means the old delta is replaced, not applied (D24). The successor states the full end state with its own test. The first form had the patcher merge the two instructions and derive its test at runtime.
- Fleet propagation: read-only drafters in every graph stop at the approval point, all edits go into one review file, a script checks each before block, Derek gives one approval, and then the same drafters apply, stamp, commit, and push. #### Learnings
- 0.6.0 broke the patch mechanism's own premise. The patch path inserts stages without renumbering and the regenerate path renumbers, so the two forked the same section's heading. Heading stability measured before any patch history existed was no evidence after it.
- A check written against the template's surface fails copies sharpened on purpose. That happened four times in one session: heading numbers, a numbering list, a literal marker, and a required case.
- Drafting every graph before applying any kept a defective shared delta unstamped, and so fixable at its source. Three drafters converging on the same complaint is what settled it.
- Recurring incidental findings across independent per-graph runs point at the shared generator. That's how the stale plugin paths showed up.
- The classifier blocked the private per-graph detail in a PR body. The same detail went into a public reference file in a plain edit and nothing stopped it.
