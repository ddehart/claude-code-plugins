⏺ I read the plugin template, this project's generated `process` skill, `graph-init`, the conventions, and `.commons.yml`. Your diagnosis is right, and I can name exactly where the inversion happened.

## What the pipeline is missing

The Aiwyn flow has four stages: **take in → preserve raw → synthesize for a human → extract graph notes from the raw**. The plugin's `process` template has eleven numbered steps, and **two of those four stages are not among them**:

| Aiwyn stage | In the template? |
|---|---|
| 1. Take in the source | Yes — steps 1–2 (Entry, Resolve) |
| 2. Preserve the raw material | **No step.** Never instructed. |
| 3. Synthesize for a human reader | **No step.** Never instructed. |
| 4. Extract notes from the raw | Yes — steps 4–6 |

The preservation gap is sharper than "it's implicit." The template never contains an instruction to **write the source note at all**. Step 3 searches for one, step 9 says "write or update the `processed:` stamp on the source note" — stamping a note whose creation is never specified. `graph-conventions.md` describes its shape ("raw and preserved — the one note type that keeps its source's own words"), but a convention describing a note's shape isn't a pipeline stage that produces it.

The synthesis gap is stranger, because the concept survived everywhere *except* the pipeline. `graph-init` interviews for it (block 2, question 9b), `.commons.yml` has a slot for it, `graph-conventions.md` documents the note shape, the README lists it as a type. Nothing anywhere writes one. A graph that answers "yes" to 9b gets a declared type and a directory that no run will ever put a note in.

## Where it turned around

Because the pipeline can't *produce* a synthesis, this project put the synthesis on the input side. `.claude/skills/knowledge-graph/SKILL.md:96` says it outright:

> **Synthesis** — none. A chronicle entry is already a session-level synthesis, so evidence is extracted straight from the source; there is no intermediate synthesis tier in this graph.

That sentence is correct about what a chronicle *is* and then draws the opposite conclusion from it. The chronicle is the human-facing synthesis of a session — written by `session-chronicle`, for a human reader. It's stage 3 of the pipeline. It got registered in `.commons.yml` as a second *source tier* instead.

Everything downstream is machinery to contain that inversion: the primary/fallback ordering, the overlapping-tier guard, the double-counting warnings, the `grep -l '"timestamp"...'` transcript-survival check, and a whole decision note (`session transcripts are primary and the chronicle is the lossy fallback`). None of that would exist if the synthesis sat on the output side, where the run produces it.

And with no preservation step, this project's raw tier degraded to a pointer into `.claude/session-exports/` — **gitignored**. The skill's own prose already records the consequence: *"That pointer can dangle, and already has."* The founding source note points at a transcript that no longer exists. Stage 2 isn't just missing from the template; its absence has already destroyed material.

⏺ One pushback before I write this up, then three remaining questions.

**On the gate.** You picked agent read-through only. That's the one choice here where being wrong is irreversible and public: a subagent reading a transcript for sensitive content is judgment, it varies run to run, and there's no way to prove it works — a planted-secret test that passes tells you it caught *that* secret, not that it catches secrets. A pattern scan is worth having underneath it precisely because it's dumb and testable: it always fires on `sk-`, `ghp_`, `-----BEGIN … PRIVATE KEY-----`, `AWS_SECRET_ACCESS_KEY=`, and a Postgres URL with a password in it, and it fails loudly when it can't run. The agent read is what catches everything else. My concern is specifically about dropping the floor, not about the read-through.

That's the whole of the objection. If you want agent-only, I'll spec it that way and say plainly in the spec that the gate is unverifiable by construction.
